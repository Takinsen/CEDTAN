## ส่วนที่ 1 — อ่านร่องรอยที่ระบบทิ้งไว้

<Why>
ระบบไฟล์บนการ์ดเปิดอ่านได้แล้ว แต่ยังไม่รู้ว่าเครื่องนี้ถูกตั้งให้ทำอะไร และไม่รู้ว่าควรเปิดไฟล์ไหนก่อน
</Why>

สองงานที่เหลือของ[ช่วงวิเคราะห์บนสำเนา](/2110413-csy/lecture-9#ขั้นตอนตั้งแต่ที่เกิดเหตุจนส่งมอบ) (งานแรกคือ carving หรือการแกะไฟล์ออกจากไบต์ดิบ) ตอบคำถามนี้

- **Analyse raw data** — อ่านข้อมูลที่เปิดดูได้ตรง ๆ บนไดรฟ์ แล้วตัดสินว่าต้องตรวจอะไรต่อ
- **Analyse system artifacts** — อ่าน <Term en="System Artifact" th="ร่องรอยที่ระบบสร้างเองระหว่างใช้งาน" /> ซึ่งเก็บข้อมูลเกี่ยวกับผู้ใช้ การ login ข้อมูล สื่อภายนอกที่เคยเสียบ เครือข่าย และอื่น ๆ ร่องรอยของ browser (browser artifacts) ก็วิเคราะห์ได้เช่นกัน

### คดีตัวอย่าง — เครื่องนี้ทำอะไรตอนเปิด

ขั้นแรกคือ mount ระบบไฟล์ที่กู้มาให้เป็นโฟลเดอร์ที่เปิดดูได้

```bash
mount image.dd /mnt/evidence/
cd /mnt/evidence/
```

คำสั่งนี้ไม่ใส่ `ro` แต่ทำกับไฟล์สำเนา การ์ดต้นฉบับจึงไม่ถูกแตะ

<Detail label="image.dd กับ evidence.img เกี่ยวกันยังไง">
ไฟล์ที่ mount ชื่อ `image.dd` ไม่ใช่ `evidence.img` และหลักฐานที่ยกมาไม่ได้บอกว่าสองไฟล์เกี่ยวกันยังไง ที่น่าจะเป็นคือ `image.dd` คือ partition ที่ถูกตัดออกจาก `evidence.img` มาเป็นไฟล์แยก

`mount` ที่ไม่ใส่ `offset=` ใช้ได้กับไฟล์ที่ระบบไฟล์เริ่มที่ไบต์แรกเท่านั้น แต่ใน image ของทั้งการ์ด partition เริ่มที่ไบต์ 8192 × 512 = 4 MiB
</Detail>

เบาะแสแรกคือระบบปฏิบัติการ ไฟล์ `etc/debian_version` บอกว่าเป็น `stretch/sid` และระบบนี้คือ **Linux Armbian** ซึ่งเป็น Linux สำหรับบอร์ดเล็กอย่าง OrangePi

<Detail label="ชื่อ Armbian มาจากไหน">
ชื่อ Armbian ไม่ได้มาจาก `debian_version` เพราะไฟล์นั้นบอกแค่ `stretch/sid` หลักฐานที่ยกมาไม่ได้บอกว่าผู้สืบรู้ชื่อนี้จากไฟล์ไหน

ค่า `stretch/sid` เป็นค่าที่ทั้ง Debian ช่วงก่อนออก Debian 9 และ Ubuntu 16.04 เขียนไว้ ค่านี้อย่างเดียวจึงบอกไม่ได้ว่า Armbian ตัวนี้สร้างบนฐานไหน
</Detail>

เบาะแสถัดมาอยู่ในสองที่ที่ทำให้โปรแกรมรันเองโดยไม่มีใครสั่ง ที่แรกคือ <Term en="rc.local" th="script ที่รันตอนบูต" /> ซึ่งระบบรันให้ทุกครั้งที่เปิดเครื่อง

```text
/mnt/evidence/etc$ cat rc.local
#!/bin/sh
# rc.local
rm /root/.bash_history
rm /root/.mobile.cfg.swp
#
switch 0
sleep 1
mobile &
exit 0
```

- `rm /root/.bash_history` ลบประวัติคำสั่งที่ root เคยพิมพ์ ทุกครั้งที่เปิดเครื่อง
- `rm /root/.mobile.cfg.swp` ลบไฟล์ชั่วคราวที่ editor ทิ้งไว้ตอนเปิดไฟล์ตั้งค่า `mobile.cfg`
- `switch 0` เรียกคำสั่ง `switch` (หัวข้อถัดไปจะเดาว่าคืออะไร) `sleep 1` รอ 1 วินาที แล้ว `mobile &` เปิดโปรแกรม `mobile` ให้รันอยู่เบื้องหลัง

ที่ที่สองคือ <Term en="cron" th="ตัวตั้งเวลารันคำสั่ง" /> ของ Unix

ตารางเวลาของมันเรียกว่า crontab ของ root บนการ์ดมีบรรทัดเดียวที่ใช้งานจริง

```text
/mnt/evidence/var/spool/cron/crontabs# cat root
...
# For more information see the manual pages of crontab(5) and cron(8)
#
# m h  dom mon dow   command
*/3 * * * * /usr/sbin/chkmobi
```

ห้าช่องแรกคือ นาที ชั่วโมง วันที่ เดือน และวันในสัปดาห์ `*` แปลว่าทุกค่า ส่วน `*/3` ในช่องนาทีแปลว่าทุก 3 นาที คือนาทีที่ 0, 3, 6 ไปเรื่อย ๆ บรรทัดนี้จึงรัน `/usr/sbin/chkmobi` ทุก 3 นาทีตลอดเวลา

คำสั่ง `file` บอกว่า `chkmobi` เป็น `POSIX shell script, ASCII text executable` เนื้อในมีแค่นี้

```sh
#!/bin/sh
if [ -z $(pidof mobile) ];then
      killall -9 mobile osmocon
      switch 0
      /usr/local/bin/mobile &
else
      echo "nothing"
fi
```

`pidof mobile` พิมพ์เลข process ของ `mobile` ที่กำลังรัน ถ้าไม่มีก็ไม่พิมพ์อะไร และ `-z` เป็นจริงเมื่อผลว่าง script นี้จึงแปลว่า **ถ้า `mobile` ไม่ได้รัน ให้ฆ่า `mobile` กับ `osmocon` ที่อาจค้างอยู่ สั่ง `switch 0` แล้วเปิด `mobile` ใหม่ ถ้ายังรันอยู่ก็ไม่ทำอะไร**

`osmocon` ส่ง firmware ที่คุมวิทยุเข้าไปในโทรศัพท์ผ่านสาย serial และเป็นทางส่งข้อความระหว่างโทรศัพท์กับโปรแกรมบนบอร์ด โทรศัพท์ที่ถูกดัดแปลงจึงต้องต่อสายเข้ากับ OrangePi

  <StartupWatchdog />
</Figure>

`debian_version`, `rc.local` และ crontab เปิดอ่านได้ตรง ๆ จึงเป็นงาน analyse raw data ส่วน `.bash_history` เป็น system artifact ที่ shell เขียนเองระหว่างใช้งาน ซึ่งเป็นเหตุที่ `rc.local` ลบมันทุกครั้งที่บูต และคำสั่งลบนั้นเองก็บอกว่ามีคนตั้งใจซ่อน ทุกอย่างบนการ์ดมีไว้ให้ `mobile` ไม่หยุดทำงาน

### script ที่สั่งขาของบอร์ด

ยังเหลือคำสั่ง `switch` ที่ `rc.local` และ `chkmobi` เรียก เบาะแสคือ start-up script ภาษา Python บนการ์ดที่คุม <Term en="GPIO" th="ขาที่โปรแกรมสั่งได้" />

GPIO คือขาโลหะบนบอร์ดที่โปรแกรมสั่งให้เป็นไฟสูงหรือไฟต่ำได้ บน Linux สั่งผ่านไฟล์ใน `/sys/class/gpio/`

ตัว script ทำสองอย่าง **ตั้งขา 11 เป็นค่าที่รับมาจาก argument ตัวแรก** แล้ว **ดึงขา 12 ลงเป็น 0 รอ 0.3 วินาที แล้วปล่อยกลับเป็น 1**

<Detail label="Python script ตัวเต็ม">
script มีสามฟังก์ชัน

- `pinexport(pin)` เขียนเลขขาลง `export` เพื่อเปิดใช้ขานั้น แล้วเขียน `out` ลง `direction` ให้เป็นขาส่งสัญญาณออก
- `pinmode(pin, mode)` เขียนค่า 0 หรือ 1 ลง `value` ของขานั้น
- `pinunexport(pin)` คืนขาให้ระบบ

```python
#!/usr/bin/python
#coding=utf-8
import os,time,sys
def pinexport(pin):
      file=open("/sys/class/gpio/export","w")
      file.write(str(pin))
      file.close()
      file=open("/sys/class/gpio/gpio"+str(pin)+"/direction","w")
      file.write("out")
      file.close()
def pinunexport(pin):
      file=open("/sys/class/gpio/unexport","w")
      file.write(str(pin))
      file.close()
def pinmode(pin,mode):
      file=open("/sys/class/gpio/gpio"+str(pin)+"/value","w")
      file.write(str(mode))
      file.close()
pinexport(11)
pinmode(11,int(sys.argv[1]))
pinunexport(11)
pinexport(12)
pinmode(12,0)
time.sleep(0.3)
pinmode(12,1)
pinunexport(12)
```

ในต้นฉบับ บรรทัดที่เปิด `direction` ถูกตัดขอบขวา argument ตัวที่สองน่าจะเป็น `"w"` เหมือนบรรทัดอื่น
</Detail>

หลักฐานที่ยกมาไม่ได้บอกว่าขา 11 และ 12 ต่อกับอะไร และไม่ได้บอกว่าไฟล์ไหนคือคำสั่ง `switch` ที่ `rc.local` กับ `chkmobi` เรียก

แต่ script นี้รับตัวเลขหนึ่งตัวเหมือน `switch 0` พอดี และการดึงขาลง 0.3 วินาทีแล้วปล่อย คือรูปแบบของการกดปุ่มหนึ่งครั้ง จึงน่าจะเป็นการสั่งเปิดหรือ reset โทรศัพท์ที่ต่อสายอยู่


<Quiz question="สมมติว่า crontab เขียนเป็น */10 * * * * แทน */3 * * * * แล้ว mobile หยุดทำงานตอน 10:01 น. มันจะกลับมารันอีกครั้งตอนกี่โมง">
`*/10` ในช่องนาทีแปลว่านาทีที่หารสิบลงตัวตามนาฬิกา คือนาทีที่ 0, 10, 20 ไปเรื่อย ๆ cron ไม่ได้เริ่มนับจากตอนที่โปรแกรมหยุด รอบถัดไปหลัง 10:01 จึงเป็น 10:10 ซึ่ง `chkmobi` จะเห็นว่า `pidof mobile` ว่างแล้วเปิดใหม่

คำตอบคือ **10:10 น.** ส่วนค่าจริง `*/3` จะได้ 10:03 น.

คำตอบที่ผิดบ่อยคือ "10:11 น. เพราะทุก 10 นาทีหลังจากหยุด" ซึ่งมอง cron เป็นตัวจับเวลาถอยหลัง แต่ cron เทียบกับเวลาบนนาฬิกาเสมอ
</Quiz>

## ส่วนที่ 2 — เปิดโปรแกรมที่ไม่มีซอร์สโค้ด

<Why>
`mobile` ที่ถูกปลุกให้รันตลอด มีบนการ์ดแค่ในรูปที่ compile แล้ว ซึ่งเป็นรหัสเครื่องที่คนอ่านตรง ๆ ไม่ได้ ก่อนจะลงแรงแกะทั้งโปรแกรม ต้องมีวิธีถูก ๆ ที่บอกได้ก่อนว่ามันเป็นโปรแกรมประเภทไหน
</Why>

### file และ strings บอกอะไรได้ก่อนเปิดโค้ด

เครื่องมือถูกที่สุดสองตัวคือ `file` ที่บอกชนิดของไฟล์ และ `strings` ที่ดึงข้อความที่อ่านออกได้ในไฟล์ออกมา สองตัวนี้ช่วยเผยชื่อบางส่วนที่อยู่ในโปรแกรม เช่นชื่อไฟล์ source

```text
/root/usr/local/bin$ file mobile
mobile: ELF 32-bit LSB executable, ARM, EABI5 version 1 (SYSV), dynamically linked,
interpreter /lib/ld-linux-armhf.so.3, for GNU/Linux 3.2.0,
BuildID[sha1]=81d28a2a833dfdddf50f9d02f77d5fc92951a408, with debug_info, not stripped
```

- `ELF 32-bit ... ARM` คือโปรแกรม Linux สำหรับ CPU ARM แบบบน OrangePi ไม่ใช่ x86 ของคอมพิวเตอร์ผู้สืบ เครื่องมือที่ต้องเข้าใจคำสั่งของ CPU จึงต้องเป็นรุ่นสำหรับ ARM เรียกว่า cross toolchain ชื่อขึ้นต้นด้วย `arm-linux-gnueabihf-`
- `with debug_info, not stripped` คือส่วนที่สำคัญที่สุด คนที่ compile ไม่ได้ลบชื่อฟังก์ชัน ชื่อตัวแปร และชื่อไฟล์ source ออกจากโปรแกรม

ดึงทุกข้อความที่มี `.c` ออกมา ได้รายชื่อไฟล์ source ของโปรแกรม

```text
/root/usr/local/bin$ arm-linux-gnueabihf-strings mobile |grep "\.c"
/root/mobile.cfg
gsm322.c
Getting PM for ARFCN %s twice. Overwriting the first! Please fix prim_pm.c
gsm480_ss.c
gsm411_sms.c
gsm48_cc.c
gsm48_mm.c
gsm48_rr.c
mnccms.c
subscriber.c
transaction.c
mncc_sock.c
l1ctl.c
l1l2_interface.c
sap_interface.c
sim.c
sysinfo.c
gps.c
main.c
....
```

เบาะแสใหญ่คือชื่อที่ขึ้นต้นด้วย `gsm` เลขในชื่อตรงกับเลขเอกสารมาตรฐานของเครือข่ายโทรศัพท์ GSM เช่น `gsm411_sms.c` รับส่ง SMS และ `l1ctl.c` คุมตัววิทยุที่อยู่ในโทรศัพท์

<Detail label="ชื่อไฟล์แต่ละตัวตรงกับมาตรฐานไหน">
| ไฟล์ | หน้าที่ |
| --- | --- |
| `gsm322.c` | เลือกเครือข่ายและเสาสัญญาณที่จะเกาะ ตามมาตรฐาน GSM 03.22 |
| `gsm48_rr.c`, `gsm48_mm.c`, `gsm48_cc.c` | คุมช่องสัญญาณวิทยุ การลงทะเบียนกับเครือข่าย และการโทร ตามมาตรฐาน GSM 04.08 |
| `gsm411_sms.c` | รับส่ง SMS ตามมาตรฐาน GSM 04.11 |
| `gsm480_ss.c` | บริการเสริม เช่นโอนสาย ตามมาตรฐาน GSM 04.80 |
| `l1ctl.c` | คุมชั้นที่ 1 คือตัววิทยุ ซึ่งอยู่ในตัวโทรศัพท์ |
| `sim.c`, `subscriber.c` | ข้อมูลซิมและข้อมูลผู้ใช้บริการ |
</Detail>

ข้อสรุปคือ **`mobile` คือซอฟต์แวร์ของโทรศัพท์มือถือ GSM ทั้งชุด ที่รันอยู่บน OrangePi** และใช้โทรศัพท์ที่ต่อสายไว้เป็นแค่ตัววิทยุ

<Example added title="ถ้าคน compile ลบชื่อทิ้ง จะเหลืออะไร">

### Reverse Engineering

ขั้นถัดไปคือ <Term en="Reverse Engineering" th="แกะย้อนว่าโปรแกรมทำงานยังไง" /> คืออ่านย้อนจากรหัสเครื่องกลับไปเป็นสิ่งที่คนเข้าใจได้ มีสองทาง

- **`objdump -d` ของ ARM cross toolchain** ในทางเทคนิคทำได้ แต่ได้ผลเป็น assembly ทีละคำสั่ง ซึ่งอ่านยากมากสำหรับโปรแกรมขนาดนี้
- **เครื่องมือที่ฟรีและดีกว่า** ตัวที่เลือกใช้ในคดีนี้คือ **GHIDRA ของ NSA** ส่วน **IDA Pro** ซึ่งเป็นของเชิงพาณิชย์อาจทำงานได้ดีกว่า แต่ผู้ตรวจในคดีนี้ไม่มี license

GHIDRA เป็น <Term en="Decompiler" th="ตัวแปลรหัสเครื่องกลับเป็นโค้ด" /> คือแปลรหัสเครื่องกลับเป็นโค้ดที่หน้าตาคล้ายภาษา C ผลที่ได้ในคดีนี้คือ **โค้ด C ที่อ่านได้ทั้งโปรแกรม** ต้นฟังก์ชัน `main` หน้าตาแบบนี้

```c
int main(int argc,char **argv)

{
  int iVar1;
  FILE *__stream;
  int __status;
  uint __seed;
  size_t sVar2;
  long lVar3;
  uint8_t *puVar4;
  uint8_t *__s;
  int *piVar5;
  osmocom_ms *ms;
  uint8_t buf [20] [100];
  char call_num [16];
```

ชื่ออย่าง `iVar1`, `sVar2` และ `puVar4` คือชื่อที่ decompiler ตั้งเองตามชนิดข้อมูล เพราะไม่รู้ชื่อจริง แต่ชนิดข้อมูล `osmocom_ms` ติดมากับ debug info และบอกตรง ๆ ว่าโปรแกรมนี้สร้างบน <Term en="Osmocom" th="ชุดซอฟต์แวร์ GSM แบบ open source" />

Osmocom คือโครงการ open source ที่เขียนซอฟต์แวร์สำหรับเครือข่ายโทรศัพท์มือถือ ส่วนที่เป็นฝั่งโทรศัพท์ชื่อ OsmocomBB และทั้ง `mobile` กับ `osmocon` ในส่วนที่ 1 ก็เป็นโปรแกรมของ OsmocomBB ส่วนถัดไปจะดูว่ากล่องเอามันไปทำอะไร

<Quiz question="ถ้าผู้ร้ายรัน strip กับ mobile ก่อนถูกจับ ผู้สืบยังรู้ได้ไหมว่ามันเป็นซอฟต์แวร์โทรศัพท์ GSM">
`strip` ลบตารางชื่อและ debug info แต่ไม่แตะรหัสเครื่องหรือข้อความคงที่ที่โปรแกรมใช้ตอนทำงาน ข้อความอย่าง `Getting PM for ARFCN %s twice...` และ `/root/mobile.cfg` จึงยังอยู่ ARFCN คือหมายเลขช่องความถี่ของ GSM

รายชื่อ `gsm*.c` ก็น่าจะยังอยู่ เพราะคำสั่ง log `LOGP` ใน `logging.h` ของ libosmocore ซึ่งเป็น library กลางของ Osmocom ส่ง `__FILE__` ไปกับทุกข้อความ แบบเดียวกับใน Detail ของตัวอย่าง strip ข้างบน

คำตอบคือ **ยังรู้ได้** ที่หายไปคือชื่อที่มาจาก debug info เช่นชนิดข้อมูล `osmocom_ms` ชื่อฟังก์ชัน และชื่อตัวแปร Ghidra ยังแปลกลับเป็นโค้ดได้ แต่ชื่อพวกนั้นจะกลายเป็นชื่อที่มันตั้งเอง

คำตอบที่ผิดบ่อยคือ "ไม่ได้เลย เพราะ strip ลบทุกอย่างที่อ่านออก" แต่ `strip` ลบได้แค่ชื่อที่โปรแกรมไม่ได้ใช้ตอนทำงาน แบบ `sim.c` ในตัวอย่าง ข้อความที่โปรแกรมต้องใช้จริงลบไม่ได้ ไม่อย่างนั้นโปรแกรมก็ทำงานไม่ได้
</Quiz>

## ส่วนที่ 3 — กล่องนี้ทำอะไร: หลักฐานจากโลกโทรศัพท์มือถือ

### โทรศัพท์เก็บอะไรไว้บ้าง

mobile device forensics หนึ่งใน[ห้าสาขาของ digital forensics](/2110413-csy/lecture-9#ห้าสาขา-แยกตามว่าหลักฐานอยู่ที่ไหน) สนใจโทรศัพท์ เพราะมันเก็บข้อมูลที่มีประโยชน์ไว้หลายอย่าง

- **ซิมการ์ดมักบอกตำแหน่งล่าสุดที่เครื่องเคยไป** เพราะซิมจดรหัสพื้นที่ของกลุ่มเสาสัญญาณที่ลงทะเบียนครั้งล่าสุดไว้
- **SMS และบันทึกการโทรเป็นหลักฐานที่มีประโยชน์** บอกได้ว่าใครติดต่อใคร เมื่อไร

### IMSI และจุดอ่อนของ 2G

<Why>
เครือข่ายมือถือต้องรู้ว่าโทรศัพท์ที่คุยด้วยเป็นของลูกค้าคนไหน เพื่อส่งสายและเก็บเงินให้ถูกคน ชื่อที่ใช้ระบุลูกค้าจึงอยู่ในซิม ไม่ใช่ในตัวเครื่อง และเครือข่ายเก็บเงินจากเจ้าของชื่อที่โทรศัพท์แจ้งมา ถ้าพิสูจน์ได้ว่าถือซิมนั้นจริง
</Why>

ชื่อนั้นคือ <Term en="IMSI" th="เลขประจำตัวผู้ใช้บริการในซิม" /> ย่อมาจาก International Mobile Subscriber Identity เป็นตัวเลขไม่เกิน 15 หลักที่เก็บในซิม ประกอบด้วยรหัสประเทศ รหัสเครือข่าย และเลขของผู้ใช้บริการ

IMSI ระบุตัว **ผู้ใช้บริการ** ไม่ใช่ตัวบัตรซิม เลขประจำบัตรซิมเป็นอีกเลขหนึ่งชื่อ ICCID เนื้อหาต้นฉบับเขียน IMSI ไว้ว่า "serial for SIM" ซึ่งตรงกับ ICCID มากกว่า

สิ่งที่ `mobile` ทำคือ **ใช้ Osmocom เป็นฐาน เพื่อดักจับ IMSI จากเครือข่าย GSM (2.5G) แล้วเอาไปซื้อของออนไลน์** เช่นของในเกมและการช็อปปิ้ง ผลคือผู้ใช้บริการที่ถูกจับ IMSI ไปถูกเก็บเงินแทน

<Callout type="info" title="ทำไมต้องเป็น 2G และทำไมโทรศัพท์ไม่มีซิม">
เนื้อหาต้นฉบับไม่ได้อธิบายว่าการรู้ IMSI ทำให้ใช้เงินของเหยื่อได้ยังไง กลไกในกล่องนี้เป็นไปได้ตามจุดอ่อนที่รู้กันของ GSM แต่หลักฐานในคดียังไม่ได้พิสูจน์

IMSI เป็นแค่ชื่อ การพิสูจน์ว่าถือซิมนั้นจริงใช้ challenge-response แบบใน [Lecture 3](/2110413-csy/lecture-3#challenge-and-response-ทำงานยังไง) เครือข่ายส่งเลขสุ่มมา ซิมตอบด้วยค่าที่คำนวณจากกุญแจลับในซิม ซึ่งไม่มีวันออกจากซิม

จุดอ่อนของ GSM คือ **เครือข่ายพิสูจน์โทรศัพท์ แต่โทรศัพท์ไม่ได้พิสูจน์เครือข่าย** ใครตั้งสถานีฐาน (เสาสัญญาณ) ปลอมได้ โทรศัพท์แถวนั้นก็ยอมเกาะและยอมบอก IMSI ให้

สถานีปลอมยังส่งต่อเลขสุ่มจากเครือข่ายจริงไปให้ซิมของเหยื่อตอบแทนได้ แบบเดียวกับ [man-in-the-middle](/2110413-csy/lecture-1#man-in-the-middle) เครือข่ายตั้งแต่ 3G ขึ้นไปปิดช่องนี้ด้วยการให้เครือข่ายพิสูจน์ตัวต่อโทรศัพท์ด้วย

โทรศัพท์ในกล่องจึงไม่ต้องมีซิมของตัวเอง เพราะมันไม่ได้ใช้ตัวตนของตัวเองเลย มันเป็นแค่วิทยุ GSM ให้ซอฟต์แวร์บน OrangePi ที่สวมตัวตนของคนอื่น

โปรแกรม GSM ที่ยกมาจากการ์ดมีแต่ฝั่งโทรศัพท์ คือ `mobile` กับ `osmocon` หลักฐานที่ยกมาจึงไม่ได้แสดงว่าส่วนไหนของกล่องทำหน้าที่สถานีฐานปลอม
</Callout>

### หลักฐานที่เชื่อมกล่องกับผู้เสียหาย

ถ้ากล่องสวมตัวตนเหยื่อซื้อของ ต้องมีคำสั่งซื้อถูกส่งออกไป บนการ์ดมีร่องรอยของ SMS แบบนั้น

| ช่อง | ค่า |
| --- | --- |
| sms sca | `+8613800230500` |
| sms | `41970` |
| ข้อความ | `CENT BST 225` |

`sca` คือ Service Centre Address หรือเบอร์ศูนย์ส่ง SMS ที่ตั้งไว้ในเครื่อง เบอร์นี้ขึ้นต้นด้วย `+86` ซึ่งเป็นรหัสประเทศจีน ปลายทางคือเลขสั้น `41970`

อีกฝั่งของเรื่องอยู่บนกระทู้ Pantip ชื่อ "เตือนภัยคนใช้ AIS-One2Call ระวังถูกหักเงินจากหมายเลข 4197005"

- เจ้าของกระทู้เพิ่งย้ายจาก TrueMove H มา AIS One2Call ได้ยังไม่ถึงสองเดือน และหลังใช้มาไม่ถึงเดือนก็ได้ข้อความจากหมายเลข `4197005` ว่า "การสั่งซื้อประสบความสำเร็จ คุณได้ชำระเงิน 26.75THB บาท โทร 023157577"
- ศูนย์บริการของ AIS ตอบว่า `4197005` คือเลขสั้นของบริการแบบจ่ายรายครั้ง ชื่อ game item and coins - **CENT BST** ราคา **ครั้งละ 25 บาท** ใช้ซื้อชีวิตในเกม NewFly บนมือถือ
- เจ้าของกระทู้ไม่เคยสมัครและไม่เคยเล่นเกมนี้ แต่ AIS ตอบว่าตรวจสอบและคืนเงินไม่ได้ ให้ติดต่อ Google Play หรือผู้ให้บริการโดยตรง

25 บาทบวก VAT 7% ได้ 25 × 1.07 = 26.75 บาท ตรงกับยอดที่ถูกหักพอดี ข้อความ `CENT BST` ตรงกับข้อความที่กล่องส่ง และ `41970` ก็เป็นต้นของ `4197005` หลักฐานจากสองฝั่งจึงชี้ไปที่บริการเดียวกัน

นอกจากนี้ยังมี **งานวิจัยหลายชิ้นที่อธิบายการใช้ osmocom แบบนี้** เช่นวิทยานิพนธ์ปริญญาโท *Shadow Phone and Ghost SIM: A Step Toward Geolocation Anonymous Calling* ของ Gerard Lawrence Pinto

<Quiz question="ผู้เสียหายรายหนึ่งถูกหักเงินจาก 4197005 ตอนบ่ายวันจันทร์ ถ้าคุณเป็นผู้สืบที่อยากรู้ว่าเงินก้อนนี้มาจากกล่องที่ยึดได้หรือเปล่า จะขอหลักฐานจากใคร และขออะไร">
ถ้ากลไกเป็นแบบในกล่องข้างบน SMS สั่งซื้อถูกส่งจากกล่อง ไม่ได้ส่งจากโทรศัพท์ของผู้เสียหาย หลักฐานที่ดีที่สุดจึงอยู่ฝั่งเครือข่าย คือบันทึกว่า SMS สั่งซื้อในนามเบอร์นี้ถูกส่งเมื่อไร ผ่านเสาสัญญาณไหน แล้วเทียบกับตำแหน่งของกล่อง

คำตอบคือ **ขอบันทึก SMS และข้อมูล cell site ของเบอร์ผู้เสียหายช่วงบ่ายวันนั้นจากผู้ให้บริการเครือข่าย** แล้วดูว่าเสาที่ใช้ส่งอยู่ใกล้ที่ตั้งกล่องไหม

คำตอบที่ผิดบ่อยคือ "ยึดโทรศัพท์ของผู้เสียหายมาเปิดดู SMS ขาออก" ซึ่งจะไม่เจอข้อความสั่งซื้อ เพราะเครื่องของผู้เสียหายไม่ได้เป็นคนส่ง มันได้รับแค่ข้อความแจ้งว่าถูกหักเงิน
</Quiz>

## ส่วนที่ 4 — Metadata: ข้อมูลที่ไฟล์พกติดตัวไปเอง

### ไฟล์มีมากกว่าเนื้อหา

<Why>
คนส่งรูปให้เพื่อนเพราะอยากให้เห็นภาพ คนส่งเอกสารเพราะอยากให้อ่านข้อความ แต่ไฟล์ทั้งสองแบบพกข้อมูลอื่นติดไปด้วย ซึ่งไม่แสดงบนหน้าจอ และคนส่งส่วนใหญ่ไม่รู้ว่ามี
</Why>

<Term en="Metadata" th="ข้อมูลที่อธิบายข้อมูล" /> คือข้อมูลเกี่ยวกับตัวไฟล์ เช่นใครสร้าง สร้างเมื่อไร ด้วยเครื่องอะไร **ไฟล์หลายรูปแบบมี metadata อยู่ในตัว และบางครั้งมันมีประโยชน์ต่องานนิติวิทยาศาสตร์**

### EXIF และ GEOTAG

<Term en="EXIF" th="ข้อมูลกล้องที่ฝังในไฟล์รูป" /> ย่อมาจาก Exchangeable Image File Format คือมาตรฐานของไฟล์รูปและไฟล์เสียงจากกล้องดิจิทัล สมาร์ตโฟน เครื่องสแกน และระบบอื่นที่จัดการไฟล์เหล่านี้ รวมถึง tag ที่ติดไปกับไฟล์ เช่นยี่ห้อกล้องและเวลาที่ถ่าย

EXIF อาจมี <Term en="GEOTAG" th="พิกัดจุดที่ถ่ายรูป" /> คือพิกัด GPS ของจุดที่ถ่ายรูปนั้น

<Example added title="รูปที่แกะออกมาใน Lecture 9.1 บอกอะไรเกี่ยวกับตัวเอง">
อ่าน EXIF ของ `carved.jpg` รูปที่ถูกลบแล้ว[แกะกลับมาจากไบต์ดิบด้วย carving](/2110413-csy/lecture-9#กู้ไฟล์ด้วยการหาหัวไฟล์)

```bash
python3 exif.py carved.jpg
```

```text
Make             Canon
Model            Canon EOS 6D
Software         GIMP 2.10.8
DateTime         2019:02:04 18:49:06
DateTimeOriginal 2014:08:21 04:44:51
LensModel        EF24-70mm f/4L IS USM
GPS none
```

รูปเดียวบอกยี่ห้อกล้อง รุ่นเลนส์ เวลาที่ถ่ายจริง และว่าถูกแต่งด้วย GIMP สี่ปีครึ่งต่อมา รูปนี้ไม่มี GPS แต่รูปจากสมาร์ตโฟนที่เปิดตำแหน่งไว้จะมีพิกัดอยู่ด้วย

<Detail label="exif.py ที่ใช้อ่านค่า">
`carved.jpg` คือรูปโปรไฟล์ขนาด 512 × 512 ที่มากับ Linux ที่ติดตั้ง GNOME script นี้ใช้ library Pillow

```python
import sys
from PIL import Image, ExifTags
im = Image.open(sys.argv[1])
exif = im.getexif()
tags = {**exif, **exif.get_ifd(0x8769)}
for k, v in tags.items():
    name = ExifTags.TAGS.get(k, k)
    if name in ("Make", "Model", "LensModel", "DateTimeOriginal", "Software", "DateTime"):
        print(f"{name:17}{v}")
print("GPS", "yes" if exif.get_ifd(0x8825) else "none")
```

`0x8769` คือกลุ่มค่าของกล้องที่เก็บแยกไว้ใน EXIF และ `0x8825` คือกลุ่มค่า GPS
</Detail>

<Detail label="thumbnail ที่เจอตอนแกะรูปใน Lecture 9.1">
header ตัวที่สองกับ footer ตัวแรกที่เจอตอนแกะรูปใน Lecture 9.1 คือ thumbnail ขนาด 256 × 256 ที่ EXIF ฝังไว้ในไฟล์เดียวกัน ตัดช่วงไบต์ 4891116 ถึง 4896185 ออกมาแล้วรัน `file` จะได้ `JPEG image data ... 256x256`

**GEOTAG เป็นภัยต่อความเป็นส่วนตัวได้** มีรายงานว่าคนดังหลายคนเผยที่ตั้งบ้านของตัวเองโดยไม่รู้ตัว ด้วยการแชร์รูปที่ถ่ายด้วยสมาร์ตโฟน

ข้อมูลส่วนตัวรั่วได้ทั้งที่ระบบไม่ได้ถูกเจาะ นี่คือเส้นแบ่งระหว่าง security กับ privacy ใน [Lecture 2](/2110413-csy/lecture-2#ส่วนที่-1--security-กับ-privacy-ไม่ใช่เรื่องเดียวกัน)

### คดี BTK — metadata ในไฟล์ที่ถูกลบ

**Dennis Lynn Rader** คือฆาตกรต่อเนื่องชาวอเมริกันที่ถูกเรียกว่า **BTK** หรือ BTK Strangler เขาตั้งชื่อนี้ให้ตัวเอง ย่อมาจาก "bind, torture, kill" ระหว่างปี **1974 ถึง 1991** เขาฆ่าคนไป **สิบคน** ในเขตเมือง Wichita รัฐ Kansas

ตำรวจพบ **metadata ที่ฝังอยู่ในเอกสาร Microsoft Word ที่ถูกลบไปแล้ว** ซึ่งยังอยู่ในแผ่น floppy disk โดยที่ Rader ไม่รู้ metadata นั้นมีคำว่า **"Christ Lutheran Church"** และเอกสารถูกบันทึกว่า **แก้ไขครั้งล่าสุดโดย "Dennis"**

คดีนี้ใช้สองเรื่องของหน้านี้พร้อมกัน คือไฟล์ที่ลบแล้วยังกู้ได้ ([Lecture 9.1](/2110413-csy/lecture-9#ส่วนที่-3--ลบแล้วไม่ได้หายไป)) และไฟล์พกชื่อคนเขียนติดไปด้วย (ส่วนนี้) คดีนี้ถูกทำเป็นภาพยนตร์ The Hunt for the BTK Killer (2005) อ่านเพิ่มได้ที่ [Dennis Rader บน Wikipedia](https://en.wikipedia.org/wiki/Dennis_Rader)

<Quiz question="แหล่งข่าวนิรนามส่งไฟล์ .docx รายงานภายในของบริษัทให้นักข่าว นักข่าวลบชื่อแหล่งข่าวออกจากเนื้อหาจนหมด แล้วโพสต์ไฟล์ต้นฉบับให้ผู้อ่านดาวน์โหลด แหล่งข่าวปลอดภัยไหม">
ไฟล์ `.docx` พกช่อง Author, Company และผู้แก้ไขล่าสุดติดไปด้วย ช่องพวกนี้ไม่อยู่ในเนื้อหา การลบชื่อออกจากเนื้อหาจึงไม่แตะมันเลย และถ้าแหล่งข่าวเปิดแก้ไฟล์ก่อนส่ง ชื่อของเขาก็อาจอยู่ในช่องผู้แก้ไขล่าสุด

คำตอบคือ **ไม่ปลอดภัย** บริษัทดาวน์โหลดไฟล์แล้วเปิด Properties ก็อาจเห็นชื่อหรือแผนกของแหล่งข่าวทันที ทางที่ถูกคือลบ metadata ก่อน หรือเผยแพร่เป็นข้อความที่พิมพ์ใหม่

คำตอบที่ผิดบ่อยคือ "ปลอดภัย เพราะในเนื้อหาไม่มีชื่อเหลือแล้ว" ซึ่งคือความผิดพลาดแบบเดียวกับของ Rader คือเชื่อว่าไฟล์มีแค่สิ่งที่เห็นบนหน้าจอ

## ส่วนที่ 5 — จะเก่งเรื่องนี้ต้องมีอะไร

คดีกล่องดักสัญญาณต้องใช้ความรู้คนละด้านในแต่ละขั้น ตั้งแต่ระบบไฟล์ การบูตของ Linux และ cron โปรแกรม ARM และภาษา C ไปจนถึงโปรโตคอล GSM คำถามว่าจะเก่งเรื่องความปลอดภัยได้ยังไง หรือจะเป็นแฮกเกอร์ได้ยังไง จึงมีคำตอบสี่ข้อ

- **ความรู้กว้างเรื่องระบบ สถาปัตยกรรม เครือข่าย โปรโตคอล และอื่น ๆ**
- **ความรู้กว้างเรื่องภาษาโปรแกรม** ขึ้นกับแอปหรือระบบที่เจอ เช่น C/C++, Python, Java และ JavaScript
- **คิดแบบคนร้าย**
- **ฝึก ฝึก และฝึก**

และต้องมี **ความอดทน** การหา partition ที่หายไป การไล่อ่าน script ทีละไฟล์ และการนั่งอ่านโค้ดที่ decompiler แปลออกมา เป็นงานที่ไม่มีทางลัด

<Recap>

**[ร่องรอยในระบบ](#ส่วนที่-1--อ่านร่องรอยที่ระบบทิ้งไว้)**

- **raw data** คือข้อมูลที่เปิดดูได้ตรง ๆ **system artifacts** คือร่องรอยเรื่องผู้ใช้ login สื่อภายนอก เครือข่าย และ browser
- คดี: Armbian (`stretch/sid`) `rc.local` ลบ `.bash_history` แล้วเปิด `mobile` ทุกครั้งที่บูต และ cron `*/3 * * * *` เรียก `chkmobi` ทุก 3 นาทีเพื่อเปิด `mobile` ใหม่ถ้ามันตาย
- Python script สั่งขา GPIO 11 ตามค่าที่รับมา และดึงขา 12 ลง 0.3 วินาที

**[อ่านโปรแกรมที่ไม่มี source](#ส่วนที่-2--เปิดโปรแกรมที่ไม่มีซอร์สโค้ด)**

- `file` บอกว่า `mobile` เป็น ELF 32-bit ARM **with debug_info, not stripped** และ `strings` เผยชื่อไฟล์ `gsm*.c` ซึ่งคือซอฟต์แวร์โทรศัพท์ GSM
- reverse engineering: `objdump -d` ทำได้แต่อ่านยาก **GHIDRA** ของ NSA ฟรีและแปลกลับเป็น C ได้ **IDA Pro** เป็นของเชิงพาณิชย์

**[หลักฐานจากโลกมือถือ](#ส่วนที่-3--กล่องนี้ทำอะไร-หลักฐานจากโลกโทรศัพท์มือถือ)**

- ซิมมักบอกตำแหน่งล่าสุด SMS และบันทึกการโทรเป็นหลักฐานที่ดี
- `mobile` ใช้ **Osmocom** ดักจับ **IMSI** จาก GSM (2.5G) แล้วเอาไปซื้อของออนไลน์ ร่องรอยคือ SMS `CENT BST 225` ไปที่ `41970` ผ่านศูนย์ SMS `+86...`
- ผู้เสียหายบน Pantip ถูกหัก 26.75 บาท (25 บาทบวก VAT) จาก `4197005` บริการ CENT BST มีงานวิจัยอย่าง *Shadow Phone and Ghost SIM* รองรับว่าทำแบบนี้ได้

**[Metadata](#ส่วนที่-4--metadata-ข้อมูลที่ไฟล์พกติดตัวไปเอง)**

- ไฟล์หลายรูปแบบมี metadata ที่มีประโยชน์ต่อการสืบสวน **EXIF** เก็บข้อมูลกล้องและอาจมี **GEOTAG** ซึ่งเป็นภัยต่อความเป็นส่วนตัว
- เอกสาร Office บอกว่าใครสร้าง ที่ไหน และบางทีมีประวัติการแก้ไข
- **BTK (Dennis Rader)** ถูกจับจาก metadata ในเอกสาร Word ที่ถูกลบบน floppy disk ซึ่งมีคำว่า "Christ Lutheran Church" และผู้แก้ไขล่าสุด "Dennis"

**[จะเก่งเรื่องนี้](#ส่วนที่-5--จะเก่งเรื่องนี้ต้องมีอะไร)**

- ความรู้กว้างเรื่องระบบ สถาปัตยกรรม เครือข่าย โปรโตคอล และภาษาโปรแกรม คิดแบบคนร้าย ฝึกให้มาก และอดทน

<Quiz question="ผู้สืบกู้การ์ดจากกล้องวงจรปิดที่ถูกดัดแปลง และเจอโปรแกรมชื่อ uploader ที่ crontab เรียกทุก 5 นาที ก่อนลงแรงแกะทั้งโปรแกรม ควรรันอะไรก่อน และผลแบบไหนบอกว่างานแกะจะง่าย">
`file` บอกว่าโปรแกรมถูก compile มาให้ CPU แบบไหน ซึ่งบอกว่าต้องใช้เครื่องมือรุ่นไหน และบอกว่าคนที่ compile ลบชื่อออกหรือเปล่า ส่วน `strings` ดึงข้อความที่อ่านออกได้ เช่นชื่อไฟล์ source หรือ path ของไฟล์ตั้งค่า ซึ่งมักบอกได้ทันทีว่าเป็นโปรแกรมประเภทไหน

คำตอบคือ **รัน `file` แล้วตามด้วย `strings`** ถ้า `file` ขึ้นว่า `with debug_info, not stripped` ชื่อฟังก์ชันและชนิดข้อมูลยังอยู่ในโปรแกรม โค้ดที่ GHIDRA แปลกลับมาจึงอ่านง่ายกว่ามาก

คำตอบที่ผิดบ่อยคือ "เปิด GHIDRA เลย เพราะสุดท้ายก็ต้องแกะอยู่ดี" ซึ่งทำได้ แต่เสียแรงกว่ามาก ในคดีกล่องดักสัญญาณ แค่รายชื่อ `gsm*.c` จาก `strings` ก็บอกแล้วว่า `mobile` คือซอฟต์แวร์โทรศัพท์ GSM ก่อนเปิดโค้ดสักบรรทัด
</Quiz>

<Quiz question="เพื่อนถ่ายรูปจานข้าวที่บ้านด้วยมือถือที่เปิดตำแหน่งไว้ แล้วส่งไฟล์รูปต้นฉบับให้คนแปลกหน้าทางอีเมล คนรับรู้อะไรได้บ้างนอกจากหน้าตาของอาหาร">
ไฟล์รูปพก EXIF ติดไปด้วย ซึ่งมีรุ่นของโทรศัพท์และเวลาที่ถ่าย และเมื่อเปิดตำแหน่งไว้ ก็มี GEOTAG ซึ่งคือพิกัด GPS ของจุดที่ถ่าย

คำตอบคือ **รู้รุ่นโทรศัพท์ เวลาที่ถ่าย และพิกัดของบ้านเพื่อน** แบบเดียวกับคนดังที่เผยที่ตั้งบ้านจากรูปที่แชร์

คำตอบที่ผิดบ่อยคือ "รู้แค่หน้าตาของอาหาร เพราะในรูปไม่มีอะไรบอกที่อยู่" แต่ EXIF ไม่แสดงบนรูป มันอยู่ในไฟล์
</Quiz>
